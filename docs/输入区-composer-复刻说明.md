# 底部输入区（composer）复刻说明

对象：鲸域 APK 0.3.0 的聊天页底部功能区。
基准：DeepSeek 官方 Android 客户端 2.6.1（`com.deepseek.chat`），在 MuMu Android 15 模拟器
（1080×2460、density 480、1dp = 3px）里逐部件量取几何与取色。

---

## 2. 我们的实现：模块 · 名称 · 顺序 · 触发行为

顺序即屏幕上从左到右、从上到下的真实排布。

| # | 模块 | 名称 / 文案 | 位置与尺寸 | 触发行为 |
| --- | --- | --- | --- | --- |
| 1 | 输入框 `input` | hint「发消息或按住说话」 | 卡片第一行，左内边距 16dp，最小高 24dp，最多 5 行 | 点击聚焦输入；IME 动作键 = 发送（等价点动作键）；**输入框非空时动作键立刻变蓝圆发送键** |
| 2 | 按住说话 `talkBox` | 「按住说话」 | 语音态时占据第一行，居中 | 按下 → 卡片上方出现提示条「松手发送，上滑取消」；上滑超过 60dp → 改为「松开取消」；松手且未取消 → 调系统语音识别；不可用则 toast「这台手机没有可用的语音识别服务，请用键盘输入」 |
| 3 | 深度思考 chip `thinkChip` | 图标 + 「深度思考」 | 第二行最左，高 30dp、圆角 15dp、图标 14dp、字 13sp、左右内边距 12dp | 点击 toggle → 写 `prefs.reasoning("high"/"")`；选中态底 = 卡片底 + 1dp 描边，未选中 = 蓝底蓝字；发消息时 body 带 `reasoning:"high"` |
| 4 | 智能搜索 chip `searchChip` | 图标 + 「智能搜索」 | 紧跟深度思考，左间距 11dp，尺寸同上 | 点击 toggle → 写 `prefs.search` 并 toast「宿主没有联网检索能力，这个开关只反映界面状态，消息不会联网」（**不发送任何请求字段**） |
| 5 | 上传键 `uploadButton` | 无文字 | 第二行右侧，44dp 触摸区，图标 26dp | 点击展开 / 收起上传面板；图标在 ⊕（`ic_upload_add`）与 ⊗（`ic_upload_close`）之间切换 |
| 6 | 动作键 `actionButton` | 无文字 | 第二行最右，44dp 触摸区，图标 26dp | 三态：① 输入为空 = 声波（点击进入语音态）② 有文字 = accent 实心圆 + 白上箭头（点击 = 发送）③ 语音态 = 键盘图标（点击回文字态） |
| 7 | 上传面板 `uploadPanel` | 拍照 / 相册 / 文件 | 卡片下方一行三块，各占 1/3 宽、高 77dp、圆角 16dp、图标 24dp + 13sp 标签 | 拍照 → 系统相机 `ACTION_IMAGE_CAPTURE` 写入 `Shot` 提供的 `content://` 后走压缩链路；相册 → `ACTION_OPEN_DOCUMENT image/*`；文件 → `ACTION_OPEN_DOCUMENT */*`，非图片 toast「目前只能发图片，其它类型的文件发不了」 |

面板展开时第二行按钮位置不动，只有 ⊕ 变 ⊗ —— 与官方一致。

## 4. 与官方的差异，以及每处的兼容处理

1. **没有卡片阴影**。官方卡片带极淡投影，我们只有 1dp 描边。做法：不引 elevation（避免与 `NoActionBar` 主题的 `stateListAnimator` 打架），保持描边；深色下官方本就几乎看不出阴影，观感一致。
2. **chip 没有水波纹**。官方 chip 点按有 ripple，我们只切换颜色（上传方块有 ripple）。做法：chip 是状态开关，颜色反转已足够提示；如需 ripple 可换成 `Theme.rippleOn(chipOff, 15f)`。
3. **语音不是真录音**。官方是自建通话链路（`CallForegroundService` + 腾讯 TRTC + 服务端 VAD/STT），宿主侧零对应能力。做法：松手后转系统 `RecognizerIntent`，识别结果**回填输入框而不自动发送**（官方是松手即发；回填可避免识别错误直接进会话）。无识别服务时给明确 toast，不静默失败。
4. **智能搜索不联网**。官方走 `/api/v0/index/*` + PoW 头，宿主没有检索能力。做法：开关只做本地状态（`prefs.search`）+ 一次性说明 toast，**不往请求里加任何字段**，因此不会触发后端 400。
5. **文件只支持图片**。官方支持文档解析，宿主 `/v1/messages` 只接受 png/jpeg/webp/gif。做法：文件面板仍按官方三格保留，选到非图片给 toast 说明，不改协议。
6. **没有草稿持久化 / 录音波形 / 系统录音权限流程**。做法：输入文字随 Activity 生命周期存在内存；权限与波形属于官方私有链路，不复刻。
7. **模型档位不放进 composer**。官方 2.6.1 的 composer 只有两个 chip，模式在模型选择器里。做法：把原来的「快速模式 / 专家模式」chip 移到右上角「⋯」菜单（「切换到专家模式 / 切换到快速模式」），底部布局与官方一致。
8. **免责声明位置**。官方把「回答由 AI 生成，仅供参考」放在消息流末尾，不在输入区下方。做法：移到 `timeline` 末尾（有消息时才显示）。
