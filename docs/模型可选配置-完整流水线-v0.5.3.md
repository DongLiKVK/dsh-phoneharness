# 模型可选择性配置 · 完整流水线（v0.5.3）

一句话：手机上现在能直接浏览、搜索、切换 harness 接入的任意模型，还能自己接一条 OpenAI 兼容网关进来；选完立刻落到手机的 prefs 和电脑端的默认模型上，建会话时把 `model` 透传给运行时。

## 1. 链路全貌

```
[手机 UI] 设置 → 模型 / composer 模型 chip
    ↓  Seats.refreshModels()
GET /v1/models            ← 宿主插件新增（server.js → runtime.models() → ModelRegistry.list()）
    ↓                       └─ ctx.get('llm').listProviders() / listModels(provider)
选择模型
    → Prefs.setModel(id, title)                     手机本地立即生效（chip 文案 + 新会话 body.model）
    → POST /v1/models/default {model, reasoning}    电脑端默认模型（agentDefaultModel.saveSelection → configEditor 写 profile）
添加外接模型
    → POST /v1/models/custom {route, displayName, baseURL, apiKeyEnv, modelIds, contextWindow?, maxTokens?}
    → 写进 llm-pi-ai 的 providers[route]（configEditor 即时应用；不可用时改 profile patch 并标记 needsRestart）
删除外接模型
    → DELETE /v1/models/custom/{route}  （若这条路由正是当前默认模型，自动把默认模型退回第一个可用模型并回 `defaultReset`）
```

宿主侧 curl 实测（全文见 docs/模型可选配置-宿主接口.md 第 8 节）：
- `POST /v1/models/default` → `{"ok":true,"defaults":{...},"applied":true}`
- `POST /v1/models/custom` → `{"ok":true,"route":"mygw","applied":true,"needsRestart":false,"backend":"configEditor"}`；重复 → 409 `custom_exists`
- `DELETE /v1/models/custom/mygw` → `{"ok":true,...}`；再删 → 404 `unknown_custom`
- 删除正在被用作默认模型的路由 → 响应多一个 `"defaultReset":"workbuddy/deepseek-v4.1-flash"`，默认模型自动回退
- 退路（`STUB_NO_EDITOR=1`）→ `{"applied":false,"needsRestart":true,"backend":"profilePatch"}`，patch 只插入目标 route、其它内容原样

## 5. 生效说明（重要）

宿主插件**没有 HMR**，`plugin/lib/*.js` 的改动要**重启一次 DSH** 才会在 8737 的真实服务里生效。重启之前手机端走的是「回落 catalog」路径（只能选内置模型，不能加外接）。重启后：
- 设置 → 模型里会出现「＋ 添加外接模型」与长按删除；
- 选择模型会同时写手机 prefs 和电脑端默认模型；
- 新增的 provider 会出现在 harness 的模型目录里，之后电脑端 App 也能选到。

外接模型的密钥不是存在配置里的：配置只写 `apiKeyEnv`（环境变量名），真正的 key 由 DSH 进程的环境变量提供，避免把明文密钥落到 profile。

## 6. 回滚

- 手机端：`adb install -r` 回 0.5.2 的包（`plugin/assets` 里覆盖前可留档）。
