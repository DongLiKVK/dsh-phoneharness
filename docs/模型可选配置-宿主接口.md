# 模型可选配置 · 宿主接口（phone-harness）

> 面向 App（Android 端）与插件的对接文档。宿主侧实现：`plugin/lib/models.js`（`ModelRegistry`）+ `plugin/lib/runtime.js` 的 5 个方法 + `plugin/lib/server.js` 的 4 条路由。
> 自测桩：`tools/stub-models-server.mjs`；一键 curl 剧本：`tools/curl-check-models.sh`。

## 1. 它解决什么

旧接口 `GET /v1/catalog` 只给「可用模型 + 默认模型 + 权限 + 工作区」，App 没法：

1. 看到每个模型的**能力**（上下文窗口、最大输出、是否支持图片、有哪些思考强度档位）；
2. **切换默认模型**并落到 profile（重启 DSH 后仍然是它）；
3. **添加一个外部 OpenAI 兼容网关**（自建代理 / 中转站），让它出现在 DSH 的模型列表里。

新接口就是这三件事，`/v1/catalog` 原样保留，旧版 App 继续可用。

## 2. 文件与调用链

| 文件 | 变更 |
| --- | --- |
| `plugin/lib/models.js` | **新增**。`export class ModelRegistry`：`list()` / `setDefault()` / `addCustom()` / `removeCustom()` / `defaultsNow()` / `invalidate()`，外加一个只用于兜底的小型 YAML 文本编辑器（写 profile patch 用）。 |
| `plugin/lib/runtime.js` | 构造时新建 `this.modelRegistry = new ModelRegistry(ctx, {...})`；暴露 `models(signal)` / `defaultModels()` / `setDefaultModel(input)` / `addCustomModel(input)` / `removeCustomModel(route)` / `invalidateCatalog()`。 |
| `plugin/lib/server.js` | 在 `handle()` 里 `const route = path.slice(4)`（鉴权之后）处新增 4 条路由；`describe()` 增加新错误码到 HTTP 状态的映射；`bearer()` 的正则从「64 位 hex」放宽为 `/^Bearer\s+([A-Za-z0-9_-]{4,128})$/`（真实鉴权仍由 `devices.find(token)` 精确比对，桩才能用 `devtoken`）。 |

宿主服务依赖（都通过 `ctx.get(name)` 取，**任何一个缺失都只降级、不 500**）：

| 服务 | 用途 | 缺失时 |
| --- | --- | --- |
| `llm`（dsh-llm-pi-ai） | `listProviders()` / `listModels(provider)` / `resolveModel()`（能力字段） | provider 列表为空，`failures` 里记一条 |
| `agentDefaultModel` | `currentSelection()` 读、`saveSelection()` 写默认模型 | `POST /v1/models/default` → 409 `default_unavailable` |
| `configEditor` | `entries()` 读 llm-pi-ai 配置、`edit()` 写入并热应用 | 退回「直接改 profile patch 文件」 |
| `profileContext` | 兜底找 `cordis.patch.yml` 路径 | 再看 `configEditor.documentPath` → `DSH_PROFILE_DIR` → `DSH_HOME/profiles/<profile>` |

## 3. 接口契约

所有接口都在 `/v1/` 前缀下，除 `/v1/ping`、`/v1/pair` 外都要 `Authorization: Bearer <token>`，与现有路由完全一致。

### 3.1 `GET /v1/models`

```json
{
  "ok": true,
  "defaults": { "model": "workbuddy/deepseek-v4.1-flash", "reasoning": "high" },
  "providers": [
    {
      "id": "workbuddy",
      "name": "DeepSeek",
      "configurable": false,
      "custom": false,
      "models": [
        {
          "id": "workbuddy/deepseek-v4.1-flash",
          "title": "DeepSeek-V4.1-Flash",
          "provider": "workbuddy",
          "model": "deepseek-v4.1-flash",
          "contextWindow": 128000,
          "maxTokens": 8192,
          "input": ["text"],
          "reasoning": ["high", "max"],
          "reasoningDefault": "high",
          "custom": false
        }
      ]
    }
  ],
  "custom": [
    {
      "route": "mygw",
      "displayName": "我的网关",
      "baseURL": "https://gw.example.com/v1",
      "apiKeyEnv": "MYGW_KEY",
      "api": "openai-completions",
      "modelIds": ["gpt-4o", "gpt-4o-mini"],
      "applied": true
    }
  ],
  "failures": []
}
```

字段语义（**加字段可以，改名字不行**）：

| 字段 | 语义 |
| --- | --- |
| `defaults.model` | `provider/model`。取值优先级：`options.readDefaults().model` → `agentDefaultModel` 的 `currentSelection()` → 第一个有模型的 provider 的第一个模型 → `null`。 |
| `defaults.reasoning` | `options.readDefaults().reasoning` → `currentSelection().reasoningEffort` → `null`。 |
| `providers[].configurable` | 这个 route 是否已经出现在 llm-pi-ai 的 `providers` 里（即「能不能被本接口改写」）。判定来源：`configEditor.entries()`，退化时读 patch 文本。 |
| `providers[].custom` | 这个 route 是**通过本接口加的**（记录在 `custom-models.json` 里）。 |
| `models[].id` | `<provider>/<model>`，直接就是 `POST /v1/models/default` 要的 `model`。 |
| `models[].title` | 优先模型自己的 `name`（`DeepSeek-V4.1-Flash`），没有才退回 `id`。App 直接显示它。 |
| `models[].contextWindow` / `maxTokens` / `input` / `reasoning` | **拿不到就整条省略**，不会给 `0` 或空数组，App 据此降级。能力来自模型配置本身，或 `llm.resolveModel()` 的 `context.contextWindow` / `defaultMaxTokens` / `inputModalities` / `reasoning.efforts`。 |
| `models[].reasoning` | 字符串数组，例如 `["high","max"]`；`reasoningDefault` 是默认档（可选）。 |
| `custom[]` | 全部自定义路由（即使 `applied:false`，即已写盘但还没生效）。按 `route` 升序。 |
| `failures[]` | 降级日志：`{scope|provider|model, message}`。**任何一项服务缺失/抛错都进这里，接口本身永远 200**。 |

### 3.2 `POST /v1/models/default`

请求：

```json
{ "model": "workbuddy/deepseek-v4.1-pro", "reasoning": "max" }
```

- `model` 必填，必须形如 `provider/model`，否则 400 `bad_model`。
- `reasoning` 可选，`[A-Za-z0-9_-]{1,16}`，否则 400 `bad_reasoning`。
- 内部调 `ctx.get('agentDefaultModel').saveSelection({provider, model, reasoningEffort})`，这条路会经 `configEditor` 把 `agent-default-model` 配置写进 profile patch 并**即时生效**。
- 服务缺失 → 409 `default_unavailable`。

响应：

```json
{ "ok": true, "defaults": { "model": "workbuddy/deepseek-v4.1-pro", "reasoning": "max" }, "applied": true }
```

`applied` 是**写后读回校验**的结果：`saveSelection()` 在没有 `configEditor` 的机器上是「静默什么都不做」，所以这里会再次 `currentSelection()` 比对；不一致时返回 `applied:false` + `note`（HTTP 仍然 200，App 可以据此提示「本次只在内存生效」）。

### 3.3 `POST /v1/models/custom`

请求：

```json
{
  "route": "mygw",
  "displayName": "我的网关",
  "baseURL": "https://gw.example.com/v1",
  "apiKeyEnv": "MYGW_KEY",
  "modelIds": ["gpt-4o", "gpt-4o-mini"],
  "contextWindow": 128000,
  "maxTokens": 4096
}
```

校验规则（逐条对应错误码）：

| 字段 | 规则 | 违反时 |
| --- | --- | --- |
| `route` | `/^[a-z0-9_-]{2,32}$/` | 400 `bad_route` |
| `baseURL` | 能被 `new URL()` 解析且 protocol 是 `http:`/`https:` | 400 `bad_base_url` |
| `apiKeyEnv` | `/^[A-Z][A-Z0-9_]*$/` | 400 `bad_env` |
| `modelIds` | 非空数组、去重、每项非空且无空白、≤128 字符 | 400 `bad_models` |
| `route` 冲突 | 已在 `custom-models.json` 或已在 llm-pi-ai `providers` 里 | 409 `custom_exists` |

写入的形状（llm-pi-ai 的 `providers[route]`）：

```yaml
providers:
  mygw:
    displayName: "我的网关"
    apiKeyEnv: "MYGW_KEY"
    api: "openai-completions"
    baseURL: "https://gw.example.com/v1"
    models:
      - id: "gpt-4o"
        name: "gpt-4o"
        contextWindow: 128000   # 传了才写
        maxTokens: 4096        # 传了才写
  docode: ...                  # 其它路由原样保留
```

响应（两条路径）：

```json
{ "ok": true, "route": "mygw", "applied": true, "needsRestart": false, "backend": "configEditor" }
```

```json
{ "ok": true, "route": "mygw", "applied": false, "needsRestart": true, "backend": "profilePatch",
  "patch": "<HOME>\\.dsh\\profiles\\desktop\\cordis.patch.yml",
  "backup": "<HOME>\\.dsh\\profiles\\desktop\\cordis.patch.yml.bak-phone-models-1792578626549" }
```

成功后 `ModelRegistry` 的 provider/route 缓存立即失效，下一次 `GET /v1/models` 就能看到新 provider（`applied:true` 时）。

### 3.4 `DELETE /v1/models/custom/{route}`

- 成功：`{ "ok": true, "route": "mygw", "applied": true, "needsRestart": false, "backend": "configEditor" }`
- route 不存在（既不在清单里也不在 llm-pi-ai 配置里）：404 `unknown_custom`。
- 能删的只有本接口加的路由；同时从 `custom-models.json` 和 llm-pi-ai `providers` 里摘掉。

### 3.5 全服务缺失时的降级实测

用假 ctx（`get()` 一律返回 `undefined`）+ 空 options 直接构造 `ModelRegistry` 实测：

```
list-with-nothing: {"ok":true,"defaults":{"model":null,"reasoning":null},"providers":[],"custom":[],"failures":[{"scope":"llm","message":"模型服务不可用，模型列表为空"}]}
setDefault code  = default_unavailable
removeCustom code = unknown_custom
```

即：`GET /v1/models` 永远 200（空列表 + `failures` 说明原因），写接口给明确的业务错误码，不会 500。

> 注意：`POST /v1/models/custom` 在 `configEditor` 缺失时会**真的去写** `profileContext`/`DSH_PROFILE_DIR` 指向的 `cordis.patch.yml`（这正是退路的设计目标）。所以「没有 configEditor 的进程」里不要随手拿它做实验，或者把 `DSH_PROFILE_DIR` 指向临时目录（桩用 `STUB_NO_EDITOR=1` + 临时目录做的就是这件事）。

## 4. 错误码总表

HTTP 状态由 `plugin/lib/server.js` 的 `describe()` 映射，响应体固定是 `{"error":{"code","message"}}`。

| code | HTTP | 触发条件 |
| --- | --- | --- |
| `unauthorized` | 401 | 没有/错误的 Bearer 令牌（现有逻辑，未改） |
| `bad_model` | 400 | `POST /v1/models/default` 的 `model` 不是 `provider/model` |
| `bad_reasoning` | 400 | `reasoning` 不是 `[A-Za-z0-9_-]{1,16}` |
| `default_unavailable` | 409 | `agentDefaultModel` 服务缺失，或 `saveSelection()` 抛错 |
| `bad_route` | 400 | route 不匹配 `[a-z0-9_-]{2,32}` |
| `bad_base_url` | 400 | baseURL 不是合法 http(s) URL |
| `bad_env` | 400 | apiKeyEnv 不匹配 `[A-Z][A-Z0-9_]*` |
| `bad_models` | 400 | modelIds 为空 / 含空白 / 超长 |
| `custom_exists` | 409 | route 已存在于清单或 llm-pi-ai providers |
| `unknown_custom` | 404 | DELETE 的 route 不存在 |
| `config_unavailable` | 503 | 找不到 patch 路径；或 `configEditor.edit()` 拒绝了这份配置（不是「暂时不可用」类错误，说明配置本身不合法，不能硬写文件） |
| `body_too_large` / `bad_json` | 413 / 400 | 请求体超 64KB / 不是合法 JSON（现有逻辑） |

## 5. 配置写在哪里

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 自定义路由清单 | `<DSH_HOME>/phone-harness/custom-models.json`（默认 `C:\\Users\\<你>\\.dsh\\phone-harness\\custom-models.json`） | 本插件自己的账本：`{version:1, routes:{route:{route,displayName,baseURL,apiKeyEnv,api,modelIds,backend,addedAt}}}`。写入用 `temp + rename`、权限 0600。`GET /v1/models` 的 `custom[]` 就来自它。`DSH_HOME` 可用环境变量覆盖。 |
| llm-pi-ai 的真实配置 | profile 的 `cordis.patch.yml` 里 `- id: llm-pi-ai` 那条的 `config.providers.<route>` | **首选**经 `configEditor.edit(entry, change)` 写：`configEditor` 自己加锁、校验、协调 profile patch 并热重载，成功即 `applied:true / needsRestart:false`。 |
| 兜底写盘 | 同一个 `cordis.patch.yml`，由 `models.js` 里的小型 YAML 文本编辑器按缩进定位 `config:\n    providers:\n` 区块插入/删除单个 route | 只在 `configEditor` 不可用（`Configuration entry is no longer available` / `changed during reload` / `EACCES` / `EPERM` / `EROFS` / `read-only` / `ENOENT`）时才走这条路。**先备份** `cordis.patch.yml.bak-phone-models-<timestamp>`，再 `temp + rename` 原子替换，其它 route 与注释一字不动。返回 `applied:false / needsRestart:true` 并带上 `patch` 与 `backup` 绝对路径。 |
| 默认模型 | profile 的 `cordis.patch.yml` 里 `- id: agent-default-model` 的 `config` | 由 `agentDefaultModel.saveSelection()` 负责，本插件不直接写这个文件。 |

**不会**做的事：不改 `android/`；不碰你现有 `cordis.patch.yml` 的内容（只在用户主动调 `POST /v1/models/custom` 时才改，且先备份）；不把 API Key 写进配置——只写环境变量名 `apiKeyEnv`，密钥本身仍由 DSH 的进程环境提供。

## 6. 什么时候需要重启 DSH

| 场景 | `applied` | `needsRestart` | 说明 |
| --- | --- | --- | --- |
| `configEditor` 可用（正常情况） | `true` | `false` | 写 profile patch 后 DSH 自己热重载，`llm` 立刻多出这个 provider；桩里实测下一次 `GET /v1/models` 就能看到并可直接选中。 |
| `configEditor` 不可用（老 profile / 只读盘 / 配置项被禁用） | `false` | `true` | 文件已经改了（有备份），但进程里没有热重载，要重启 DSH 才会出现。`custom[]` 里该条 `applied:false`，App 可以显示「待重启生效」。 |
| 切默认模型 | —— | —— | `saveSelection()` 成功后立即生效；返回 `applied:false` 说明这台机器没有 `configEditor`（写不进 profile）。 |

> 注意：本插件是宿主插件，**改 `plugin/lib/*.js` 需要重启 DSH 才加载**（没有 HMR）。上面的「热生效」只针对配置数据，不包括插件代码本身。

## 7. 自测桩 `tools/stub-models-server.mjs`

不需要真的 DSH：桩用一个**假 ctx**（`llm` 两个 provider、`agentDefaultModel` 内存实现、`configEditor` 内存实现）把真实的 `HarnessRuntime` + `PhoneServer` 拉起来，所以走的完全是线上那份代码。

### 7.2 手机端怎么连

1. 手机与 PC 同一局域网，APK 里填 `http://<LAN_IP>:8799`（换成你的 PC 局域网 IP；`ipconfig` 看）；
2. 配对码填 `000000` → 拿到 `devtoken`；
3. 之后所有请求带 `Authorization: Bearer devtoken`；
4. 先 `GET /v1/ping` 确认通，再 `GET /v1/models`。

### 7.3 一键跑完全部用例

```bash
node tools/stub-models-server.mjs &          # 或另开一个窗口
bash tools/curl-check-models.sh              # 默认 http://127.0.0.1:8799 devtoken
```
